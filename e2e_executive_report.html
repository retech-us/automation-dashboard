The 5-Step Intelligent Reset Execution Journey Full Operational Lifecycle

Here is exactly what happens from the moment an associate stands in front of a grocery shelf to when reset compliance is completed:

📸 1. Photo Upload
Mobile → AWS S3 Cloud

Associate takes a panoramic bay photo. Our framework adapters (Android/iOS) load real shelf JPEGs, request S3 tokens via POST /api/v4/processing/upload/request/, stream raw multipart bytes to S3, call finish/, and register the scan via POST /api/v4/processing/actions/.

🧠 2. AI Processing
Hawkeye Computer Vision

AI detects every product box, reads UPC barcodes, and compares physical shelf facings against Target Planogram (POG) from GET /api/v4/planograms/{id}/.

⚙️ 3. Action Generation
Planogram Solver Engine

Backend calculates mathematical differences between shelf reality and planogram goal. Generates raw action records via GET /api/v1/tasks/{id}/action-list/retailer/.

📱 4. Mobile Display
UI Card Model Mapping

Android & iOS map backend rows into swipeable cards sorted in store-walk order: Identify → Remove (Delisted/Expired) → Set Aside (HOLD) → Fix / Restock in Bay.

🛒 5. Physical Actions
Associate Reset Execution

Associate removes delisted items off shelf into cart, slides items into position, adds restock products, taps 'Done' on cards, and takes a post-photo to verify compliance.

Automated Synchronization Engine: How We Keep Tests in Sync with Mobile & Backend Code Zero Manual Maintenance

To guarantee that tests never drift from production code, our automation framework employs a 4-pillar continuous synchronization engine:

1. Git Source Resolution & Commit Pinning

Controlled by core/git_source_controller.py. The orchestrator inspects the exact branch and commit SHAs of rebotics-management-django, android-rebotics, and ios-rebotics before execution. Any new commit automatically triggers contract validation.

2. Static AST Reflection on Mobile Repos

The engine automatically parses Kotlin Retrofit interfaces (@Query annotations) and Swift Moya Target endpoints (Task.requestParameters). If mobile developers add a new query parameter (e.g. version=2 or section), the test framework detects and incorporates it without code rewrite.

3. Dual-Sided Dynamic Contract Verification

core/api_contract_verifier.py executes synthetic queries with and without optional parameters against Django DRF endpoints. It verifies backward compatibility, validates that unauthenticated requests fail cleanly, and asserts that required parameters return valid status codes (HTTP 200).

4. Automated CI/CD Regression Gates

Implemented in .github/workflows/shelf-intelligence-regression.yml. Whenever a PR is created in any of the 3 repositories, the workflow runs this full suite. If a backend PR renames or removes a query parameter that mobile depends on, the build is blocked with a red gate before reaching QA.
